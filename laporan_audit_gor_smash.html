1. Ringkasan Eksekutif & Temuan Kritis

Terdapat pemisahan total (disconnection) antara backend dan frontend:

  • Frontend (api/public/app.html): Merupakan prototipe mandiri (offline mock) yang berjalan penuh di browser menggunakan localStorage (kunci: gorsmash_v5). Frontend sama sekali tidak memiliki kode fetch() atau axios ke endpoint REST API backend.
  • Backend (Laravel 13): Menyediakan 16 endpoint REST API di routes/api.php dengan basis data PostgreSQL/SQLite yang saat ini belum pernah terhubung atau menerima request dari frontend.
  • Kontradiksi Dokumentasi: api/README.md menyebutkan bahwa web langsung menggunakan endpoint API yang sama, padahal kenyataannya frontend masih berupa mock data lokal.

3. Fitur Backend yang Belum Ada / Belum Dikonsumsi Frontend

  • Konsumsi Endpoint Transaksional: GET /api/jadwal, POST /api/booking, POST /api/booking/{kode}/bukti-dp, GET /api/admin/pembayaran, POST /api/admin/booking/{kode}/pelunasan.
  • Health Check Endpoint (GET /api/health): Belum ada tampilan status koneksi backend di UI.
  • Ringkasan Finansial CRM Pelanggan: Endpoint GET /api/admin/pelanggan/{no_hp}/riwayat mengembalikan agregasi total omset, frekuensi sewa, dan jumlah batal yang belum ditampilkan di UI admin.
  • Monitoring Agregat Status Booking (GET /api/pemilik/monitoring-booking): Pengelompokan status otomatis dari backend belum dipakai.

4. Fitur Frontend yang Belum Didukung Backend

  • Sistem Pengajuan Tiket Permohonan (db.req): Menu permohonan batal atau reschedule oleh pelanggan via menu Cek Booking.
  • Manajemen Master Metode Pembayaran oleh Pemilik (o-bayar): Fitur CRUD rekening bank, e-wallet, dan QRIS dinamis oleh pemilik.
  • Layar Piutang & Trigger Auto-Cancel Manual (o-piutang): Tombol eksekusi auto-cancel 2 jam dari web. Di backend ini berjalan melalui artisan CLI schedule.
  • Tabel Publik Booking Terbaru: Daftar 12 booking terakhir yang disamarkan nomor HP-nya di halaman Cek Booking.

5. Rekomendasi Solusi

  • Langkah 1: Ganti fungsi penyimpanan lokal state.db di app.html dengan fungsi fetch('/api/...') terpusat.
  • Langkah 2: Simpan token bearer yang didapat dari POST /api/login ke dalam sessionStorage browser.
  • Langkah 3: Sinkronkan master data seeder backend agar konsisten dengan frontend (misal menambahkan Lapangan 4).
  • Langkah 4: Putuskan model permohonan pembatalan/reschedule: buatkan tabel permohonan di backend atau ubah UI frontend agar admin yang menginput perubahan langsung.
